## 浏览器+API 模式优化：登录后提取请求头并关闭浏览器
- 需求：browser_api（浏览器登录+API签到）模式下，浏览器登录成功后只取了 Cookie，没取请求头；且 `login_and_refresh_cookies` 登录成功后**没关浏览器**（只 `BrowserExecutor.run` 的 finally 会关，但 browser_api 走的是这个独立方法，浏览器泄漏）。
- 改动：
  - `executors/base.py` 的 `SignContext` 新增 `self.browser_headers = {}`。
  - `executors/browser.py`：把 `_remember_ua` 升级为 `_capture_browser_headers(ctx, driver)` —— 登录成功后用 JS 读 `navigator.userAgent`/`navigator.language` + 当前页 URL，提取 `User-Agent`/`Accept-Language`/`Referer`/`Accept` 写入 `ctx.browser_headers`，UA 同时写入 `ctx.vars['ua']`（兼容旧 `{{ua}}` 模板）。
  - `login_and_refresh_cookies` 在两个成功分支都调用 `_capture_browser_headers`，并在 `try/except` 后加 `finally` **始终 `self.driver.close()` 并置 None**（修复浏览器不关闭）。
  - `executors/api.py` 的 `_do_request`：构建请求头后，把 `ctx.browser_headers` 作为**默认值合并**（步骤显式配置优先，不覆盖）；UA 缺失/为 `{{ua}}` 空值时优先用浏览器 UA 再回退 `DEFAULT_UA`。
- 验证（`.venv` 真连 pting.club + 本地 HTTP 回显）：
  1. `_capture_browser_headers` 正确提取 UA/Accept-Language/Referer/Accept；
  2. `login_and_refresh_cookies`（假账号触发失败分支）结束后 `be.driver is None`、chrome 进程 before/after 均为 0 → 浏览器已关闭无泄漏；
  3. API 请求实际收到 `User-Agent=浏览器UA`、`X-Custom=步骤头保留`、`Accept-Language`/`Referer` 已合并 → 请求头统一生效。
- 注意（已修正）：`browser_headers` 现已**持久化**到 sites 表 `headers` 列（plain JSON）。

## 补丁：浏览器请求头持久化（避免下次纯 API 签到丢失统一请求头）
- 用户反馈：登录成功后编辑站点页只看到 Cookies，没看到请求头；且 `browser_headers` 原本只存在 `ctx`（会话级），未落库 → 下次有 Cookie 直接 API 签到时就没有统一请求头。
- 改动：
  - `models.py`：`init_db` 用 `_add_column_if_not_exists` 加 `headers TEXT` 列（幂等，旧库自动迁移）；新增 `update_site_browser_headers(sid, headers_json)`。
  - `executors/base.py`：`SignContext.__init__` 改为 `self.browser_headers = self._load_browser_headers()`（从 `site['headers']` plain JSON 加载），新增 `_load_browser_headers()`。
  - `executors/sign_service.py`：每次运行后（与成功与否无关）调用 `update_site_browser_headers` 写回 `ctx.browser_headers`。
  - `app.py` + `templates/add_edit.html`：编辑站点页在 Cookies 下方只读展示已提取的浏览器请求头。
- 验证（本地 HTTP 回显 + DB 往返）：新增 api 站点 → 写回 headers → 重新 `get_site`+`SignContext` 加载 → API 请求实际收到 `User-Agent=TestBrowserUA/9.9` 且步骤自定义头保留 → 全链路 PASS。验证脚本 `_verify_persist.py` 已删除。
- 用户反馈"还是没保存请求头"：直接查 `data/auto_sign.db` 证实 s28（browser_api 模式）的 `headers` 列**已有完整数据** → 持久化代码生效。真正原因是用户运行中的 Web 服务没重启、`add_edit.html` 模板改动未加载，编辑页看不到。结论：**改完 app.py/模板后必须重启 Flask（及调度进程）；Docker 需重建镜像/重启容器，否则源码改动不生效。**

## 新增第 4 种签到模式 `buddy`（整合 Buddy 加油站签到）
- 需求：把 `D:\.Buddy\Buddy-signin`（WorkBuddy/Buddy加油站令牌式签到）整合进 PT-signin，作为「添加站点」的方式，不破坏现有三种模式；并实现「一次读取登录态永久登录」（自动续期）。
- 结论：原生 browser/api/browser_api 都做不到（api 模式 login 不回写 token 致续期链断）。方案：新增隔离的 `buddy` 模式。
- 改动：
  - 新增 `executors/buddy.py`：`BuddyExecutor(mode='buddy')`，复用 buddy_checkin.py 三接口；Bearer+X-User-Id+X-Domain 头；`code==0`/`10001`/已签到 判成功；自动读桌面登录态文件或 token_store；续期后 `_persist_token_store` 回写。
  - `executors/base.py`：`SignContext` 新增 `self.token_store = self._load_token_store()`（解密 `site['token_store']`）。
  - `models.py`：`init_db` 加 `token_store TEXT` 列；新增 `update_site_token_store(sid, enc)`（enc=None 清空）。
  - `executors/__init__.py`：注册 `BuddyExecutor`。
  - `app.py`：`_render_form` 解密展示 token_store + buddy 字段回显；`_build_buddy_config`（auth_file/api_bases/domain）；`add`/`edit` 路由处理「令牌」框（粘贴校验/清空）；`buddy` 模式用专属 config 组装。
  - `templates/add_edit.html`：新增 `#secBuddy` 区块（令牌文本框 + 授权文件/API域名/默认Domain）+ `switchMode()` 联动。
- 验证（本机 Windows 真连）：用假 site 调 `get_executor('buddy',ctx).run()` → 自动读桌面登录态、自动续期（有效期至 2026-11-16）、签到返回「✅ 今日已签到」、success=True。全链路 PASS。注意：该测试会真实命中一次 API（幂等），并因 PYTHONIOENCODING 默认 gbk 导致含 ⛽ 表情消息打印报 UnicodeEncodeError，需设 utf-8。
- 使用方式：添加站点 → 模式选「Buddy令牌签到」→ Windows 端「令牌」框可留空（自动读登录态），NAS/Docker 端粘贴 Windows 导出的 token_store JSON 一次即可，续期自动滚动。Buddy 签到按本项目 sign_times 时间表、按站点顺序执行（不自带 times）。原 Buddy 项目的 `buddy_chat.py`（连续登录遥测上报）未整合，属可选增强。

## 推送消息统一简化为「只发结果」
- 用户补充要求：消息推送与其他站点统一格式，只推签到结果（签到成功/签到失败/今日已签到），不要日期/续期/积分/签到方式标注（这些保留在日志）。
- 改动：`executors/buddy.py` 的 `run()` 改为 `SignResult(True/False, '签到成功'/'今日已签到'/'签到失败', None, detail)`，日期/续期/积分汇总/失败原因全部 `ctx.log`；`_do_claim` 返回状态枚举 `success/already/fail` 供 run 映射文案。同步收敛 `browser.py`（移除 `（检测到标识）`/`（点击按钮后）` 标注 → 日志；失败文案统一 `签到失败`）与 `api.py`（最终判定与 Cloudflare/步骤异常详情 → 日志，推送 `签到成功`/`签到失败`）。
- 推送拼接在 `sign_service.run_all_scheduled_sign`：`f"{status} {name} - {msg}"`，故最终推送行如 `✅ Buddy - 今日已签到`。验证通过（真连返回 `今日已签到`）。
- 约定：所有 `SignResult.message` 只含结果短句，诊断信息写 `ctx.log`。
