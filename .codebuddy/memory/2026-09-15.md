# 2026-09-15

## Bug 修复：API 登录接口配置不保存
- 根因：模板 `add_edit.html` 中站点顶部「登录地址」与登录接口区块的「登录地址」都用了 `name="login_url"`，表单提交时 `request.form.get('login_url')` 只取第一个（顶部，纯 api 模式通常为空），导致 `_build_api_config` 里 `if login_url and mode=='api'` 不成立，登录接口配置被整体跳过、未入库；再次打开编辑页全部丢失，且运行时 `has_login=False` → 签到裸发 → 提示「请先登录」。
- 修复：登录接口区块字段改名为 `login_api_url`（模板 317 行、app.py 构建处、_render_form 回显处三处同步）。新建 `executors/api.py` 的 `_run_login` 在未单独配置时继承全局 `verify_ssl`/`follow_redirect`，避免关掉全局 SSL 校验后登录请求仍默认 True 而失败。
- 注意：登录接口简易配置区块仅在「API 模式 + 简易配置」标签页下显示（`refreshLoginSection` 控制）；JSON 配置模式 / browser_api 模式看不到。

## Bug 修复：Docker 环境中文响应乱码（Windows 正常）
- 现象：同一条 `{"code":401,"message":"请先登录"}`，Windows 正常，飞牛NAS Docker 显示为 `иҐ·е…Ӣ...` 乱码（UTF-8 字节被按 Latin-1/CP1252 解码）。
- 根因：服务端响应未带 charset，`api.py` 原来用 `resp.apparent_encoding` 探测编码，结果随环境的 charset 探测库版本不同而变（Windows 探到 UTF-8，Docker 探到 Latin-1）。
- 修复：`executors/api.py` 的 `_do_request` 改为——Content-Type 无 charset 时优先 `resp.content.decode('utf-8')` 校验后设 `resp.encoding='utf-8'`，仅当不是合法 UTF-8（老站 GBK）才退回 `apparent_encoding`。这样跨环境一致，且不影响关键词判定（乱码会导致 not_contains 匹配失败）。
